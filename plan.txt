# 《神秘时代》 游戏计划书

**项目代号：** Aether Fragment / 以太残响（暂定）
**文档性质：** 概念设计与技术路线计划书
**目标平台：** 浏览器（桌面优先，移动端兼容）
**核心原则：保留“研究—要素—风险”的解谜内核，剥离 Minecraft 的沙盒载体与资源逻辑。**


## 一、原模组元素盘点与剥离清单

《神秘时代》的许多系统之所以成立，是因为它们“长在 Minecraft 身上”。一旦脱离方块世界，这些系统要么失去意义，要么可以用更适合 HTML 的方式重新表达。先把“必须剥离的 MC 依赖”和“值得保留并独立化的机制内核”分开。

### 1.1 必须剥离的 载体

| MC 元素 | 在原模组中的作用 | 剥离原因 | 替代方向 |
|---|---|---|---|
| **方块放置/挖掘/合成网格** | 所有物品、祭坛、研究台都以方块形式存在 | HTML 游戏不具备自由 3D 方块编辑的必要性 | 2D 静态场景 + 面板式交互；研究台、注魔台以“全屏界面”呈现 |
| **物品栏 / 背包 / 耐久** | 资源管理与工具损耗构成压力 | 物品栏是沙盒生存的产物，与研究解谜内核无关 | 改为“要素库存”与“灵感/墨水”抽象资源 |
| **生物群系（魔法森林、腐化之地）** | 灵气节点分布、生物生成、探索目标 | 开放世界探索成本高，且依赖地形生成 | 用“区域”或“关卡”抽象替代：每个区域有固定的灵气属性与腐化倾向 |
| **战斗系统（法杖射击、傀儡战斗）** | 法杖作为武器、怪物作为威胁 | 战斗不是《神秘时代》的不可替代内核 | 删除即时战斗；威胁由“腐化蔓延”和“研究失败”承担 |
| **维度 / 下界 / 末地** | 部分高阶材料来源 | 与核心循环无关 | 不设多维世界，用“异域裂隙”作为事件而非常驻地图 |
| **原版生物（僵尸、骷髅等）** | 填充世界、提供掉落 | MC 知识产权与风格绑定 | 全部移除；仅保留或重新设计“灵气生物”作为叙事符号 |


### 1.2 值得保留并独立化的机制内核

真正让《神秘时代》具有辨识度的，不是“在 MC 里造祭坛”，而是以下几层设计：

**第一层：要素本体论。** 万物可被分析为六种元始要素（风、地、火、水、秩序、混沌）及其复合产物。这是一种“世界可被理解”的认知模型，不依赖任何 MC 实体。

**第二层：研究即解谜。** TC4 的研究台用六边形网格承载要素，规则是“两个相邻要素若存在合成关系则可连接”，玩家需要把初始要素全部连成通路。这本质上是一个图论连线谜题，天然适合 HTML/SVG 交互。

**第三层：风险与取舍。** 注魔有风险值，祭坛不对称、环境不达标会引发闪电、爆炸、咒波泄漏；灵气节点被过度抽取会“死亡”并消失。压力不来自怪物，而来自玩家自己的贪婪与规划失误。

**第四层：腐化作为反馈。** 腐化不是单纯的“坏区域”，而是污染积累到阈值的可见后果：土地变色、生物异变、灵气场失衡。它可以被设计为 HTML 游戏中最重要的“长期压力仪表”。


## 二、独立化后的核心系统设计

### 2.1 要素系统：从“六元始”出发

保留六元始要素：**风（Aer）、地（Terra）、火（Ignis）、水（Aqua）、秩序（Ordo）、混沌（Perditio）** 。复合要素不追求原模组 44 种的规模，初期设计 12—18 种，每一种都对应一个 HTML 界面中的**可交互研究对象**（一件“遗物”、一种“材料”或一个“现象”）。

要素的获取方式不再是“扫描方块”，而是：

- **解析**：在“解析台”界面中，将一件物品/遗物拖入六边形分析槽，系统根据预设的要素构成逐格揭示；
- **合成**：在“要素合成”界面中，将两个已知要素拖入合成位，若存在合法复合关系则生成新要素并记入图鉴；
- **残留**：研究失败或注魔事故会留下“咒波残渣”，可作为混沌要素的低效来源——让错误也有产出，但产出带着代价。

### 2.2 研究系统：六边形连线谜题作为核心交互

这是 HTML 版本最应该“原样保留并放大”的部分。TC4 研究笔记的规则简洁而富有深度：六边形网格中，如果要素 A 是要素 B 的合成成分（或反之），则 A 与 B 可连接；玩家的任务是把所有初始要素纳入同一条连通路径。

在 HTML 中的具体设计：

- **渲染**：SVG 或 Canvas 绘制六边形网格，每个格子是一个可放置要素的“槽位”；
- **操作**：从左侧“要素库存”拖拽要素到网格中；已放置要素可右键撤回（但不返还，制造决策成本）；
- **连接判定**：前端维护一张“要素合成关系表”，实时检测相邻六边形是否满足连接条件，并用高亮线段标出已连通的边；
- **完成条件**：所有初始要素被连接在同一连通分量中，研究解锁；
- **难度曲线**：前期谜题网格 7—12 格，只涉及元始要素之间的直接合成；中期引入复合要素作为“桥梁”，网格扩大至 19—37 格；后期出现“不可直接连接、需要绕行”的拓扑设计，对应原模组中“折一下”或“回环”的解法。

研究系统不消耗“真实时间”，只消耗要素库存与“墨水/灵感”抽象资源。一次研究失败不导致 game over，但会扣除要素并可能产生咒波残渣，把失败反馈到腐化系统中。

### 2.3 灵气与节点：从“世界生成”变成“可管理的场”

TC4 的灵气节点有普通、凶险、纯净、污染、饕餮、不稳定等类型，且存在“过度抽取导致节点死亡”的机制。在 HTML 游戏中，不生成 3D 世界中的节点，而是把“灵气”设计为每个**区域页面**的全局资源条：

- 每个研究区域或事件场景拥有一个**灵气场**，由 1—3 个“节点”抽象构成；
- 节点提供特定要素的“可抽取量”，抽取用于研究或注魔，但抽取会降低节点稳定度；
- 节点稳定度归零则“枯竭”，该区域该要素来源永久关闭（或在长冷却后以“凋零节点”形式恢复，但产出减半）；
- **纯净节点**可以被玩家“培育”：消耗秩序要素与特定研究解锁，将一个普通节点转为纯净节点，提升恢复速率并抑制腐化。这为玩家提供了一条“修复而非榨取”的路线。

这套设计把原模组中“满世界找节点”的探索，压缩为“在有限区域中做资源规划”的决策，更适配 HTML 的单页交互节奏。

### 2.4 腐化系统：长期压力仪表

腐化在 HTML 版本中承担两个功能：**惩罚贪婪**和**制造叙事氛围**。

腐化的来源：

- 注魔研究时风险值过高，产生“咒波泄漏”；
- 在腐化倾向区域过度抽取灵气；
- 连续研究失败积累的“残渣”未处理。

腐化的表现（纯前端可实现的轻量反馈）：

- 页面整体色调逐渐偏紫/偏暗（CSS filter 或 overlay）；
- 部分可交互要素图标出现“畸变”版本，点击时产生随机负面效果（如扣除额外要素、暂时锁定某个槽位）；
- 当腐化值越过阈值，解锁一个“腐化事件”页面：玩家必须在“清除腐化（消耗纯净要素/秩序要素）”和“接受腐化换取短期研究加速”之间选择。

腐化不会直接结束游戏，但它会持续侵蚀玩家的资源效率，形成一种“慢性失控”的压迫感——这正是原模组腐化机制最有魅力的部分。


## 三、HTML 实现的技术路线

### 3.1 前端架构

单页应用即可承载全部内容。核心模块包括：

- **状态管理**：一个轻量的 central store，维护要素库存、已解锁研究、节点状态、腐化值、当前区域。
- **六边形网格**：优先使用 **SVG**。六边形用 `<polygon>` 绘制，连接线用 `<line>` 或 `<path>`，每个格子绑定点击/拖拽事件。相比 Canvas，SVG 的事件绑定和样式控制更直接，适合研究台这种“少量、高交互密度”的场景。可选库：`react-hexgrid`（若使用 React）或 `honeycomb`（纯 TS/JS）。
- **拖拽**：HTML5 Drag and Drop API 足够覆盖“从库存拖到网格”的需求；移动端 fallback 为“点击选中 → 点击槽位放置”。
- **动画与反馈**：CSS transition 处理连接线闪烁、要素图标放置/撤回的位移；腐化 overlay 用 `filter: hue-rotate` 或半透明渐变层实现。
- **持久化**：`localStorage` 保存研究进度、要素库存和腐化值，支持“续玩”。不需要后端。

### 3.2 要素关系表的数据结构

核心是一张可静态配置、也可运行时查询的关系表：

```js
// 示例结构
const aspects = {
  aer:    { name: '风', type: 'primal', symbol: '🌪' },
  terra:  { name: '地', type: 'primal', symbol: '⛰' },
  ignis:  { name: '火', type: 'primal', symbol: '🔥' },
  aqua:   { name: '水', type: 'primal', symbol: '💧' },
  ordo:   { name: '秩序', type: 'primal', symbol: '⚖' },
  perditio:{ name: '混沌', type: 'primal', symbol: '🌀' },
  // 复合要素
  gelum:  { name: '寒', components: ['aqua', 'perditio'] },
  victus: { name: '生命', components: ['aqua', 'terra'] },
  // ...
};

// 连接判定：a 与 b 可连接 ⇔ a 是 b 的 components 之一，或 b 是 a 的 components 之一
function canConnect(a, b) {
  return (aspects[b]?.components?.includes(a)) 
      || (aspects[a]?.components?.includes(b));
}
```

研究谜题的“初始要素集合”和“可用六边形槽位布局”可以序列化为 JSON，便于设计关卡和后续扩展。

### 3.3 分阶段开发计划

**第一阶段：可玩原型（约 2—3 周）**

目标：验证“六边形要素连线”在浏览器中的手感。

- 实现单个研究谜题界面：固定网格、拖拽放置、连接判定、完成检测；
- 要素库存为硬编码数值，不做灵气/腐化系统；
- 美术使用占位符（符号 + 纯色块）。

**第二阶段：核心循环闭环（约 3—4 周）**

目标：让“解析 → 获得要素 → 研究 → 解锁新要素/配方 → 再解析”跑通。

- 加入解析台（从“遗物”中获取要素）；
- 加入 3—5 个连续研究关卡，解锁复合要素；
- 引入墨水/灵感消耗，使研究有节制；
- localStorage 保存进度。

**第三阶段：灵气与腐化（约 3—4 周）**

- 实现区域式灵气节点：每个区域有 1—3 个节点，抽取消耗稳定度；
- 实现腐化累积与 CSS 视觉反馈；
- 加入一个“腐化事件”抉择界面；
- 调整数值，使“过度抽取→腐化→效率下降”形成可感知的负反馈循环。

**第四阶段：内容填充与打磨（持续）**

- 将研究关卡扩展至 15—20 个，覆盖主要复合要素；
- 加入纯净节点培育、咒波残渣处理等支线决策；
- 响应式适配移动端，优化触屏拖拽/点击；
- 叙事碎片嵌入（以“遗物描述”“研究笔记残页”形式）。


## 四、美术与叙事方向

**视觉基调：** 避开 Minecraft 的像素方块语言。《神秘时代》的辨识度来自“炼金术手稿”与“禁忌知识”的氛围，而非像素。HTML 版本可以采用**羊皮纸底色、暗铜色线条、紫/青作为要素强调色**的视觉体系。六边形网格本身就像一个炼金术阵图，不需要方块来支撑。

**要素图标：** 每个要素使用一个几何符号 + 一个色彩编码。元始要素用简洁的几何形（三角、圆、折线、螺旋等），复合要素由组成它的元始符号叠合或变形生成——让玩家在看图标时就能“读出”它的构成。

**叙事框架：** 玩家扮演一名“残响解析者”，在一个灵气正在枯竭的世界中，通过解析遗物和研究禁忌知识来理解世界的底层要素结构。没有 MC 的“史蒂夫”，没有生物群系，只有散落的遗物、残破的研究笔记和一片正在腐化的灵气场。腐化不是“敌人”，而是这个世界对“过度索取”的回应。


## 五、关键取舍与风险

**放弃沙盒，接受“有限棋盘”。** 失去自由放置方块的表达力，换来的是每一个交互都被精心设计的密度。研究谜题和灵气管理本身就是足够深的策略空间，不需要开放世界来填充。

**不追求复刻全部 50 种要素。** 原模组的要素数量部分服务于“万物皆可扫描”的沙盒需求。HTML 版本只需要 12—18 种高辨识度、高使用率的要素，每一种都拥有清晰的获取路径和研究用途，避免图鉴变成收集负担。

**腐化不能沦为“读条惩罚”。** 腐化的视觉反馈和事件抉择必须让玩家感到“这是我自己造成的结果”，而不是随机降临的 debuff。每一次过度抽取、每一次高风险注魔，都应该在界面上留下可见的痕迹。

**最大技术风险在六边形网格的移动端交互。** 桌面端的拖拽体验容易做好，触屏上的精确放置和撤回需要额外的点击流设计。建议第一阶段就在手机浏览器上测试，而不是等桌面原型完成后再适配。


**一句话总结：** 你要做的不是“把 MC 模组搬进浏览器”，而是把《神秘时代》中真正不可替代的那件事——**用解谜的方式理解世界、并为理解付出代价**——抽出来，用六边形、要素库存、灵气场和腐化仪表重新承载它。HTML 的 SVG 和 CSS 动画足以让这套内核成立，而 MC 的方块、生物和物品栏，一样都不需要。
